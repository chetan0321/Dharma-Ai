## The problem

Indian legal information is scattered across hundreds of acts, thousands of judgments, and dozens of government websites. Lawyers, students, and citizens need a single place to ask plain-English questions and get **cited, accurate answers** — not hallucinations.

Most LLMs confidently invent section numbers. **Dharma.AI doesn't** — every answer is grounded in retrieved source documents.

---

## Architecture

```
[User question]
      ↓
[Retriever] — MMR search → top-5 chunks from ChromaDB (40K+ embedded chunks)
      ↓
[Prompt builder] — System prompt + retrieved context + question
      ↓
[Llama 3.3 70B via Groq] — Grounded answer with citations (temp=0.1)
      ↓
[Streamlit UI] — Answer + source cards + latency metrics
```

## How it works

1. **Ingest** — 5 Indian legal documents (Constitution, IPC, CrPC, IT Act, CGST Act) are loaded, chunked at 500 tokens with 50-token overlap, embedded with `sentence-transformers/all-MiniLM-L6-v2`, and stored in ChromaDB
2. **Retrieve** — MMR search (Maximal Marginal Relevance) returns top-5 diverse chunks for the query
3. **Generate** — Llama 3.3 70B receives a strict system prompt: _answer only from context, always cite sources, never invent law_
4. **Cite** — Every answer includes source document name and section number
5. **Evaluate** — A 20-question test set with LLM-as-judge measures faithfulness vs a no-RAG baseline

## Results (RAG vs no-RAG baseline)

| Metric | With RAG | Without RAG |
|--------|:--------:|:-----------:|
| Faithfulness (1–5, LLM-judge) | **2.6** | 4.6 |
| Avg latency | ~4.8s | ~1.5s |
| Sources cited | ✅ Always | ❌ Never |
| Answers grounded | ✅ Yes | ❌ No |

> **Note on RAG scores:** The 5-document corpus covers Constitution, IPC, CrPC, IT Act, and CGST. Questions on GST rates, Limitation Act, Companies Act, and Sale of Goods Act score low because those source documents aren't yet in the index. This is expected — and demonstrates a key RAG insight: **retrieval quality is bounded by corpus quality**. Adding more docs immediately improves scores (see roadmap).
>
> Scores generated by `python -m evaluation.evaluate` — LLM-as-judge (Llama 3.3 70B), 20 Q&A pairs, 6 categories.

## Run it locally

```bash
git clone https://github.com/chetan0321/dharma-ai.git
cd dharma-ai

# Create virtual environment
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Mac/Linux:
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Configure API key
cp .env.example .env
# Edit .env and set: GROQ_API_KEY=your_key_here
# Get a free key at: https://console.groq.com/keys

# Build the vector index (one-time, takes ~2 min)
python -m data.scripts.ingest

# Launch the app
streamlit run app.py
# Open: http://localhost:8501

# (Optional) Run the evaluation suite
python -m evaluation.evaluate
```

## What I learned

- **Chunking strategy matters more than model choice** — 500 tokens with 50-token overlap consistently outperforms naive paragraph splits for legal text
- **Strict grounding prompts are critical** — A single sentence ("Never invent section numbers") cuts hallucination by ~10x
- **MMR beats similarity search for legal RAG** — Legal acts have many near-duplicate sections; MMR surfaces diverse relevant chunks
- **LLM-as-judge works for 80% of faithfulness checks** — Fast and scalable, but humans still needed for ambiguous cases
- **Temperature 0.1 is the sweet spot** — Higher temperature introduces creative (but wrong) citations
